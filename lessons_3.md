# Секция 1: Топ-3 MCP-серверов

## #1: DeepADB
**Ссылка:** https://mcpservers.org/servers/fullread/deepadb

**Что делает:**  
DeepADB — это MCP-сервер для глубокой интеграции с Android Debug Bridge (ADB).  
Он позволяет AI-клиенту работать с подключённым Android-устройством: выполнять ADB-команды, анализировать состояние устройства, управлять приложениями, собирать логи, изучать UI hierarchy, записывать экран, работать с эмуляторами и автоматизировать тестовые сценарии.

**Какие tools предоставляет:**  
По описанию сервер предоставляет большой набор инструментов для работы с Android-устройством, включая:

- выполнение ADB-команд
- управление приложениями
- чтение состояния устройства
- сбор `logcat`
- анализ UI hierarchy
- запись экрана
- работу с эмуляторами
- сетевую и диагностическую информацию
- automation / CI-oriented сценарии

**Почему выбран:**  
Я выбрала DeepADB, потому что он выглядит самым мощным и practically useful для Android-разработки.  
Лично для меня он интересен тем, что связывает AI не просто с текстовыми подсказками, а с реальными инструментами Android-инженера. Такой сервер может быть полезен для отладки, диагностики багов, автоматизации рутинных действий и тестирования приложений на устройстве.

## #2: MCP Android Agent
**Ссылка:** https://mcpservers.org/servers/nim444/mcp-android-server-python

**Что делает:**  
MCP Android Agent — это MCP-сервер, ориентированный на автоматизацию взаимодействия с Android-устройствами и Android-сценариями.  
Он ближе не просто к “набору ADB-команд”, а к агентному подходу, где AI может выполнять более осмысленные действия в Android-среде.

**Какие tools предоставляет:**  
По доступному описанию сервер ориентирован на инструменты для:

- автоматизации действий на Android-устройстве
- выполнения Android-oriented сценариев
- управления средой и приложением
- поддержки агентных workflows для mobile automation

**Почему выбран:**  
Я выбрала этот сервер, потому что мне интересна именно идея более “умного” уровня над Android tooling.  
Если обычные ADB-серверы дают низкоуровневые команды, то Android Agent потенциально полезен для сценариев автоматизации, smoke-тестирования, воспроизведения шагов пользователя и QA-задач. Для команды мобильной разработки это может помочь быстрее проверять гипотезы и автоматизировать повторяющиеся действия.

## #3: Apktool
**Ссылка:** https://mcpservers.org/servers/SecFathy/APktool-MCP

**Что делает:**  
Apktool MCP server даёт инструменты для работы с APK-файлами.  
Он полезен для анализа собранного Android-приложения, изучения ресурсов, структуры пакета и содержимого AndroidManifest.

**Какие tools предоставляет:**  
По назначению такого сервера можно ожидать инструменты для:

- декомпозиции APK
- анализа структуры приложения
- просмотра ресурсов
- анализа manifest
- задач reverse engineering и inspection

**Почему выбран:**  
Я выбрала Apktool, потому что он закрывает совсем другой класс задач, чем ADB-серверы.  
Если DeepADB и похожие решения работают с устройством, то Apktool помогает работать с самим артефактом приложения. Это полезно для диагностики проблем сборки, анализа APK, понимания структуры приложения и обучения тому, как устроен Android package после сборки.

# Секция 2: Топ-3 Skills для Claude Code

## #1: test-driven-development
**Ссылка:** https://github.com/obra/superpowers/tree/main/skills/test-driven-development

**Что делает:**  
Этот skill помогает Claude Code использовать подход **TDD (Test-Driven Development)**, то есть сначала формулировать ожидаемое поведение через тест, а потом писать реализацию.  
Он задаёт более дисциплинированный процесс работы над новой функциональностью или исправлением багов.

**Как активируется:**  
Skill активируется, когда в Claude Code задача формулируется как реализация фичи или bugfix через тест.  
По описанию он предназначен для использования **до написания implementation code**, чтобы сначала определить ожидаемый результат, а потом переходить к реализации.

**Почему выбран:**  
Я выбрала этот skill, потому что для Android-разработки он особенно полезен в логике `ViewModel`, `use case`, `repository`, обработке состояний и бизнес-правил.  
Он решает важную проблему: код часто пишется быстрее, чем проверяется. Такой skill помогает сначала зафиксировать ожидаемое поведение, а уже потом писать реализацию. Для команды это полезно снижением числа регрессий и более предсказуемыми изменениями.

---

## #2: using-git-worktrees
**Ссылка:** https://github.com/obra/superpowers/blob/main/skills/using-git-worktrees/

**Что делает:**  
Этот skill помогает использовать **git worktrees** для параллельной работы над несколькими задачами в одном репозитории.  
Он позволяет вести несколько независимых рабочих директорий для разных веток и не ломать текущее состояние проекта постоянными переключениями.

**Как активируется:**  
Skill используется в Claude Code, когда нужно безопасно работать сразу с несколькими задачами: например, отдельно поддерживать feature-ветку, hotfix и эксперимент.  
Он особенно полезен в ситуациях, где нежелательно постоянно делать `checkout`, `stash` и вручную восстанавливать контекст.

**Почему выбран:**  
Я выбрала этот skill, потому что он очень практичен для Android-разработки.  
Мобильные проекты часто тяжёлые: Gradle-сборки занимают время, локальное состояние может быть чувствительным к переключению веток, а задач параллельно обычно несколько. Для меня этот skill полезен тем, что помогает аккуратно разделять рабочие контексты. Для команды это уменьшает хаос при параллельной разработке и ускоряет переключение между задачами.

## #3: subagent-driven-development
**Ссылка:** https://github.com/NeoLabHQ/context-engineering-kit/tree/master/plugins/sadd/skills/subagent-driven-development

**Что делает:**  
Этот skill помогает организовать разработку через несколько подзадач и подагентов: разбивать работу на независимые части, запускать отдельные потоки выполнения для разных задач и затем собирать результат с промежуточными review-checkpoints.

**Как активируется:**  
Skill активируется, когда задача в Claude Code достаточно большая и её нужно декомпозировать на несколько частей: например, изменение логики, обновление тестов, правка документации и проверка архитектурных ограничений.  
Он подходит для controlled development workflow, где важны последовательность и контроль качества между итерациями.

**Почему выбран:**  
Я выбрала этот skill, потому что в Android-разработке задачи часто состоят сразу из нескольких слоёв: UI, бизнес-логика, данные, навигация, тесты.  
Такой skill полезен тем, что помогает не смешивать всё в одну большую правку, а двигаться более структурированно. Для команды это особенно ценно в крупных фичах, где легко потерять фокус или пропустить зависимость между слоями приложения.
